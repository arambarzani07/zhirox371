# V35 — paginated canonical stock movement history

The stock history now pages `retail_stock_events` directly with 50 rows per request, exact RLS-scoped counts, deterministic created_at/id descending order and a fixed upper timestamp for each browsing session. Direction, reason group, Baghdad period and exact registered barcode filters execute on the server before pagination. Barcode lookup includes inactive/retired catalog aliases and validates the store and product identity; generated scale-label codes not explicitly registered are not resolved by this filter. Text search remains an explicitly labeled current-page filter over product names, locally loaded barcode text and reason labels. It is not a global free-text search.

Stock receipt RPCs already append canonical stock events. Their companion audit events must not be counted as additional stock movements. The old audit-union fallback is removed; audit-only records are not represented as real stock changes. Optional, RLS-visible stock-adjustment notes enrich matching request/product rows on the current page only and never contribute quantities or counts. Missing or denied note reads do not invalidate canonical stock history.

Product name and base unit are embedded from the row's actual foreign-key relationship, selecting only id/store_id/name/base_unit, without costs. This avoids relying on the bounded product catalog for old movements. RLS-hidden metadata remains unknown; unknown units are excluded from quantity totals. Unit and kg totals describe filtered rows on the current page, not all store history. The current-stock column still reflects the separately loaded balance cache, not historical or freshly verified balances.

Loading/error clears rows and metrics and disables navigation/export. Filter edits invalidate in-flight reads immediately; request/store/actor guards discard obsolete replies after a newer query or logout. An emptied last page moves back to the remaining final page. Offset pages are not a repeatable-read database snapshot: concurrent backdated inserts or deletion can still shift rows; refresh resets the timestamp.

CSV covers visible rows on the current page and includes explicit units and Baghdad timestamps. Filenames identify the page range and matching history total. The self-contained preview forwards CSV generation to its owning top-level page so exports work outside the sandboxed iframe. The message bridge checks source identity and only accepts CSV downloads.

No schema, grants, RLS policies, financial write RPCs, production database or locked Home assets are changed. Verification covers 263 events over six pages, remote filters, retired barcode lookup, joined units outside the catalog, canonical/audit non-duplication, scoped notes, malformed replies, read failure, shrinking pages and delayed responses. Browser checks cover the real bundled PC pages and downloadable CSV. New headless-browser and disposable Auth/JWT/PostgREST checks are included for CI; they have not run remotely until the changes are pushed.
