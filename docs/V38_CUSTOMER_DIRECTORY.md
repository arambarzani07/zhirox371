# V38 — customer directory pages and explicit action selection

The active customer directory now pages `retail_customers` directly, 50 rows at a time, with exact RLS-scoped counts and name/id ordering. Literal search by a selected name/phone/address/note field and positive-debt/nonpositive-balance filters execute on the server before pagination. Wildcard characters `%`, `_` and backslash are escaped; the unsupported `*` shortcut is rejected. Unknown fields/status values cannot become query columns.

Metrics and CSV cover visible page rows, not the bounded mutation cache or full-store debt totals. Over-credit-limit filtering remains an explicitly labeled current-page checkbox because the existing API does not provide a server cross-column comparison. Its checkbox changes visible rows without redefining the server page count. Negative customer balances are labeled prepaid credit. Directory rows require active/store-matching identity, safe integer balances and nonnegative credit limits; malformed counts, duplicate IDs and overflow fail closed.

Directory row actions no longer rely on the target being in the first 500 cached active customers. Account reloads fetch missing explicitly requested/selected active customers with store/id-scoped exact lookups, then validate aggregate money before populating selectors. Payment, debt and history forms preserve the requested identity after asynchronous snapshot refreshes. Missing/inactive/denied target records fail instead of substituting another customer. Edit opens from a fresh exact customer read with actor/store/identity guards. Profile-save acknowledgments cannot reset or repopulate a different authenticated session's form. The financial write RPCs themselves are unchanged.

Directory loading/error, account refresh, filter change and logout clear page rows and metrics and disable export/navigation. Request/store/actor guards discard obsolete read replies. Empty final pages recover to the last remaining page. This is live offset pagination over mutable names/balances, not a repeatable-read snapshot; concurrent edits can shift rows between requests.

CSV exports visible rows, includes full customer identity, neutralizes text formulas and names the server source page range. The old misleading directory debt metric label inherited from the payment-card change is corrected to page debt.

No production database, schema, grants, RLS policies or locked Home assets are changed. The mutation dropdowns and debt overview remain a bounded cache with explicitly pinned customer lookups; this change does not provide full-store debt summaries, global over-limit counts, unbounded dropdowns or complete historical statements. Remote CI has not run on the local changes.

Local verification covers 623 active customers across 13 pages, literal field search and server debt filters, safe money/count validation, scoped exact lookup, stale read/logout protection, final-page recovery and out-of-cache customer hydration. The real bundled PC preview verifies the last 23 rows, server search beyond 500, fresh edit opening, the requested payer and current amount after selector refresh, and downloadable page CSV. Headless-browser and disposable Auth/JWT/PostgREST checks are included for CI.
