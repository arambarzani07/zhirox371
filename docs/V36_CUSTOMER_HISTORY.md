# V36 — server-paginated customer ledger history

The history tab now reads `retail_customer_ledger` independently from the bounded customer/account snapshot. Each request returns 50 rows with exact RLS-scoped counts, descending created_at/id order and a fixed upper timestamp per browsing session. Customer, entry-type and Baghdad date filters run on the server. Exact phone lookup includes inactive customers, requires one unambiguous store-matching result and never guesses among duplicate numbers. Current-page text search remains explicitly labeled as such.

Each ledger row embeds only its customer's id/store_id/name/phone. Historical names do not depend on the first 500 active customers being loaded. Hidden related records remain unknown and are identified by customer_id. Missing counts, duplicate row IDs, foreign stores/related customers, invalid timestamps, unsafe integers and malformed ledger totals fail closed.

Loading, error, account refresh, a newer filter and logout clear the history rows and printable summary. Request/store/actor guards discard obsolete replies. An emptied last page moves back to the remaining final page. Offset pagination with an upper timestamp is not a repeatable-read database snapshot: concurrent backdated inserts/deletes can still shift rows.

Metrics describe debt added/reduced and net debt change on the visible page. They no longer substitute the sum of the bounded customer balance cache for history totals. CSV uses the same visible rows, includes signed debt changes and authoritative per-entry balance_after_minor, and identifies its source page range in the filename. Printed summaries describe one customer's visible page rows and explicitly state that they are not complete historical account statements. Mixed-customer pages require a customer selection before printing.

Remaining limits: the directory, mutation selectors, debt view and customer-payment view still use the explicit bounded account snapshot. This change removes the 500-row history browsing cutoff only. It does not implement full customer statements, full-store debt totals, paginated payment-only cards or unbounded customer selection. Phone matching is exact; duplicate phone numbers require selection from the loaded directory.

Financial RPCs, production schema, permissions and locked Home assets are unchanged. Verification covers 623 rows across 13 pages, server phone/customer/type filters, inactive customer metadata beyond the bounded directory, malformed/denied reads, money validation, shrinking pages, stale responses and logout. The real offline PC preview was checked across 523 records, including rows 501–523, printable page scope, phone/type filtering, empty results and downloaded CSV. New headless-browser and disposable Auth/JWT/PostgREST checks are prepared for CI; remote CI has not run on this local commit.
