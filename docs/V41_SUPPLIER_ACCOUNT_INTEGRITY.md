# V41 — Supplier and purchasing read integrity

Supplier, purchase-order and supplier-ledger snapshots now use three canonical, store-scoped server reads with exact counts and a deterministic limit of 500 each. All three must succeed. Invalid counts, partial responses, duplicate/foreign rows, unsafe monetary integers, malformed purchase quantities or ledger dates reject the whole snapshot. Local persisted data is not a fallback for a failed server read.

During loading or failure, old rows, printable account/order boxes, selectors and monetary metrics are cleared. Monetary values show an em dash, and purchasing submissions, supplier payment, quick amounts, exports and account printing are disabled. Token/store/actor checks reject stale read replies. Logout clears supplier data and edit state. A shared Refresh action retries the read.

All four purchasing views label their metrics as loaded data. A read-scope status exposes loaded/total supplier, order and ledger counts. Supplier account printing is labelled loaded transactions instead of a complete statement; the directory action uses the same wording. Negative supplier balances are labelled prepaid. Changing a selected supplier clears the previous payment amount.

Explicit directory-to-order, receiving and payment actions use the verified snapshot without starting a competing asynchronous reload. Purchase-order receiving preserves its selected supplier and invoice. Report shortcuts wait for the purchasing read. Order creation/cancellation refresh canonical snapshots after acknowledgement. Profile, order, receiving and payment UI acknowledgements check the originating identity. Supplier ledger acknowledgements validate returned balances, deduplicate entry IDs and retain only the latest 500 loaded entries.

Validation: 255 local Node tests and syntax/assets build passed, including denied reads from all three tables, malformed/foreign/duplicate rows, aggregate overflow, read races and obsolete/deduplicated supplier acknowledgements. Manual PC checks verified loaded/total 500/523 counts for all three datasets, explicit supplier payment selection, clearing the payment amount on supplier change and exact supplier/invoice preservation when opening receiving from a purchase order. Authored browser and actual Auth/PostgREST CI scenarios are syntax-checked but await remote CI execution.

Limits: snapshots, local search, exports, supplier statements, selectors and low-stock pending-order checks remain bounded to loaded records. No global store-debt total or complete statement is claimed. Supplier pagination and server searching, server-owned order/invoice numbering, broader offline transport and complete purchasing history remain follow-up work. SQL, financial RPC definitions, grants, RLS, locked Home, production database and PC Relay are unchanged.
